Lecture seule.` ; `tools: Read, Glob, Grep`. Le prompt système impose : analyser le besoin fourni et le code existant du projet ; produire en sortie un **brouillon de spec** en Markdown contenant obligatoirement les sections *Contexte*, *Périmètre*, *Critères d'acceptation* (chacun objectivement testable), *Hors-périmètre*, *Risques*, et une section *Questions ouvertes* qui ne liste que les points **bloquants**, chacun avec la réponse par défaut retenue si personne ne répond. Le brouillon est proportionné au besoin : un besoin trivial tient en une vingtaine de lignes et quelques critères, sans question. Interdits : inventer une exigence non déductible du besoin ou du code ; modifier un fichier ; proposer une implémentation détaillée (c'est le rôle du Builder).
Classer chaque question ouverte de la spec (BQ-10) : **bloquante** si la construction ne peut pas commencer sans la réponse et qu'aucune option par défaut n'est défendable, sinon non bloquante. Chaque question est un élément `- Q<n> — <texte>` ; une question non bloquante porte une sous-ligne `Défaut : <option justifiée>` (obligatoire) ; les bloquantes sont listées sur la ligne `Questions bloquantes : Q<n>, …` (ou `aucune`) placée juste sous la ligne `Statut :`. Écrire aussi `Périmètre fichiers : <globs relatifs à la racine, séparés par des virgules>` quand la spec peut le borner.
